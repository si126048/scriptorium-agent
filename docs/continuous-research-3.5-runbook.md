# Scriptorium 3.5 连续研究运行说明

## 日常使用

在项目中直接提出问题。一次提问对应一条连续研究时间线：说明、计划、来源获取、阅读发现、最终回答与报告入口。当前活动默认展开，完成后收起；手动展开保持。最终回答接收实际模型分片，不在完成后播放打字动画。不显示隐藏思维链或原始方法 JSON。

上翻阅读后停止跟随，新增内容通过“查看新进展”提示。输入草稿与文稿独立保存。点击引用打开正确版本并高亮；完整报告仍在右侧阅读，转入文稿后编辑。项目、主要模型及来源筛选使用统一弹层。

停止保留已有内容；恢复复用来源对象、导入与已完成步骤。预算决定继续使用原研究回合，拒绝追加时结束并保留阶段成果。技术错误在对应回合处理，旧等待结果不能覆盖新失败或续跑状态。

## 材料获取

默认原生联网与 Crossref、OpenAlex、Open Library 的公开小批量接口结合，不需要付费搜索密钥。书目查询只提交问题与公开书目信息，材料原文不作为查询自动外发。项目外发与联网政策继续生效。

Crossref 用于 DOI 和书目识别；OpenAlex 补充开放位置；Open Library 用于作品、语言及版本线索。开放接口认证、限流和超时只影响对应渠道，不自动购买额度或更换付费服务。中文与人文专著覆盖有限，目录记录不等于取得原文。

默认上限：4 万 token、六节点（包含最终写作预留）、两轮修订、3 次原生发现、12 次开放接口 HTTP 请求、20 个候选作品、10 份正文、每作品最多 3 个访问位置、20 MiB/份、100 MiB 累计。重试计入 HTTP 请求及下载额度，未知传输和模型消耗保留预留。

来源优先复用项目原件，再尝试登记的开放位置。不同译本和版次不按相似标题合并。只有书目的来源保留版本未确认状态；只有摘要的材料明确标注摘要，不能作为全文或原书页码。正文使用 Trafilatura 2.3.1 本地提取，网络获取仍由项目公共地址校验层负责。登录、付费、借阅与验证码不绕过。

自动选段从全部候选片段检索，默认仍为有界的代表性阅读，约 6000 code point；不是整部作品已经读完。未读窗口保留在覆盖记录中。取得足够材料后可先形成阶段结果，不因每一项受限来源都暂停。

## 数据、恢复与诊断

新增后续迁移 research_0007：时间线内容块、来源访问位置、获取尝试及元数据请求。旧迁移未改写，旧来源 ID、文本版本及锚点保留。先备份，再使用新的 API 与 Worker；不让旧后台与新版同时处理同一研究库。

会话 SSE 复用现有通道。新增 timeline.block 事件包含稳定内容块、执行代次、修订和 code point 偏移；snapshot 返回完整草稿与游标，重连后去重，拒绝旧代次并检测缺口。消息接口保持兼容；新增 conversations/{cid}/timeline、research-tasks/{job_id} 类型化读取。来源详情增加 locations、attempts、version_status。

最终写作是一个独立记账步骤，先预留额度再调用。正文完成并通过允许引用集合检查后发布正式报告；失败保留草稿和账本，显式继续才会重新尝试。模型原生发现和普通生成能力仍受供应商配置约束。

scriptorium-research doctor 增加本地正文提取自检。运行日志记录任务、阶段与错误类别，不记录密钥和完整模型提示。备份、恢复、撤回与 GC 覆盖新增表和原始对象；撤回清理时间线及对应事件内容。

## 交付边界

本轮面向个人 Windows 工作台，不扩展服务器和多人协作。不调用付费模型，不组织学术能力评分。真实公开接口可用性、模拟流式检查与实际安装验证分别记录；候选及散列见本轮验收报告。
