## 1. 本轮发现及修复

研究主任务会在子任务被另一 Worker 占用时让出执行。原实现将主任务重新排队，但没有恢复本次调度占用的尝试次数，也没有延迟再次领取。当 Worker 中断后子任务租约尚未到期，恢复中的主任务可能反复领取、让出，耗尽默认三次尝试后停留在无法领取的队列中。

本轮修复：

- 让出执行时退还本次尝试；进程崩溃消耗的尝试仍保留。
- 排队任务以 `lease_until` 表示最早可领取时间，短暂延迟领取，避免主任务持续抢占子任务。
- 让出时清空租约令牌，使旧执行者无法继续心跳或提交结果。
- 对非正数租约和最大尝试次数拒绝启动，避免无效配置破坏恢复语义。

不涉及表结构调整，无需新增 Alembic 修订。相关文件：`scriptorium/research/service.py`、`workspace.py`、`config.py`。

## 4. 验收记录的有效性

修订 `scripts/run-acceptance.ps1`：

- 运行前后计算代码散列；期间代码变化则判为无效。
- 源库散列变化直接导致命令失败，而非仅在摘要提示。
- 从 JUnit 读取测试数量、跳过、失败和错误；正常完整验收中跳过测试会导致命令失败。
- 摘要分别记录 `code_unchanged`、`test_counts` 和 `automated_verification_complete`。
