# Qwen 真实调用与项目完善审查

日期：2026-10-24（北京时间）  
范围：使用用户本轮提供的密钥临时连接 Qwen，并检查统一工作台与研究流水线。密钥仅在测试进程中使用，未写入项目文件、测试产物或本文档。

## 1. 结论

**Qwen 连接正常，但真实研究流水线仍有阻断性问题，暂不宜将工程测试通过解释为真实研究已可稳定使用。**

现有证据校验正确地拒绝了不合法引文，没有把失败伪装为演示成功；需要改进的是模型输出如何可靠地转换成原文证据，以及失败调用如何记账。

本轮只测试原创合成材料，没有向模型发送用户研究材料。使用独立 PostgreSQL schema、独立对象目录，没有切换正式数据，也没有修改业务代码。原有 350 项工程回归结果仍是代码检查记录，不代表下列真实模型案例通过。

## 2. 真实调用结果

连接：项目既有 DashScope 中国区兼容接口；模型 `qwen-plus`。先进行一次极短连接测试，成功返回；随后在既有研究流水线中执行 Q-03、Q-05，各设置 40,000 token 的研究预算，无演示回退。遇到失败后没有自动扩大预算或反复重试。

| 案例 | 关注点 | 实际结果 | 对方法质量的结论 |
|---|---|---|---|
| Q-03 | 没有有效内在矛盾时是否停止，不强造概念转化 | 失败：`CITATION_OUTSIDE_READ_WINDOW` | 尚无法评价；首个方法产物未成功提交 |
| Q-05 | 可消解的术语／事实差异是否被误判为视差 | 失败：`QUOTE_RANGE_MISMATCH` | 尚无法评价；首个方法产物未成功提交 |

两组均没有提交成功的锚点，数据库记录的 `used_tokens` 均为 0。这不是“引文零异常而通过”，而是失败事务没有产出可验收证据。既然已取得模型响应，调用用量应被独立记录，不能因后续证据校验失败而消失。

证据位置：

- `output/qwen-review-20261024/connection.json`
- `output/qwen-review-20261024/qwen_review_96f7e4299b804d88b2225fd668c29267/summary.json`
- 同目录 `Q-03.json`、`Q-05.json`：合成材料、任务状态、步骤及产物检查。

本轮未完成 Q-01…Q-08 的全部真实调用，也没有独立研究者签认，不宣称三种方法已通过学术验收。

## 3. 按优先级完善

### P0：先打通真实模型的证据落地

位置：[引文转换与校验](../../hermeneut/research/methods.py:205)。

当前要求模型输出摘录及 Unicode code point 起止位置，随后直接按位置校验。两次真实调用分别出现越界和范围／摘录不一致，研究因此中断。模型能理解文字不等于能稳定计数。

建议让原文摘录及片段身份成为定位输入，由程序在不可变原文中精确查找：唯一精确匹配时登记位置，并记录是否校正了模型给出的位置；重复摘录必须利用上下文或明确消歧，不能取第一次出现；没有精确匹配则保留失败并进行有次数及预算上限的修正请求。不要通过模糊匹配或删除校验制造“成功”。还应识别输出被截断、非法 JSON、限流和网络错误，向用户提供明确的恢复操作。

完成条件：Q-03、Q-05 可实际完成并保留原文锚点；重复引文、emoji 和组合字符仍通过；无效证据仍被拒绝。

### P0：模型调用账本与产物事务分开

位置：[取得模型用量](../../hermeneut/research/methods.py:175)、[成功步骤后才记账](../../hermeneut/research/workspace.py:189)。

当前只有产物成功保存后，研究运行才累计用量。真实案例因引文验证失败，调用已发生，运行却显示消耗 0。手工重试会继续调用，但无法从现有运行台账完整追溯开销。

建议为每次请求登记独立的调用尝试，包含预留、开始时间、模型、返回用量、失败阶段及关联步骤。API 已返回的用量应在产物失败时仍保留；超时且实际用量未知时显式记录未知，不能按 0 处理。估算应覆盖系统提示、schema、历史摘要、原文及输出上限，而非只计算当前原文加固定常数。

完成条件：引文错误、JSON 错误、超时、重试及恢复均可对账，不会绕过预算；凭证不进入账本。

### P1：让“当前选区”真正限定请求

位置：[发送请求](../../web/src/features/workspace/UnifiedWorkspace.tsx:289)、[选区操作](../../web/src/features/workspace/UnifiedWorkspace.tsx:373)。

界面显示原文选区，但发送时没有把选区范围或 `segment_ids` 传给服务。部分操作只是把摘录放进问题，或加入整份材料。这使“用于研究”与用户看到的范围不完全一致。

建议区分本次研究的“选区／片段／整份材料”；发送稳定文本版本和 code point 范围，服务端核对；引用仍回到原文版本。输入区直接显示研究范围，取消选区后也应同步清除请求中的范围。

完成条件：选择一句话研究时不会默认读取整份材料，范围与覆盖记录一致；跨项目、跨版本范围不能混用。

### P1：从逐段调用升级到跨文本论证

位置：[按窗口安排全部方法](../../hermeneut/research/workspace.py:111)、[仅传最近八个产物](../../hermeneut/research/workspace.py:164)、[每项只传前 1,200 字摘要](../../hermeneut/research/methods.py:138)。

目前构境、内在批判、视差与审查主要按每个窗口分别运行。跨页展开的立场、尺度和反例无法保证在同次检验中出现；后续只获得有限摘要，没有完整传递证据关系。分支虽保存前提，但创建子方法任务时没有将该前提作为独立输入传入。

建议分为“分批阅读登记 → 项目内概念／立场／证据汇集 → 针对论点检验 → 回原文寻找反例 → 修订”。背景不足时先保留构境未知；只有存在待检验立场或不同观察位置时才调用相应方法。把分支前提、研究问题、材料版本和证据关系一同传递。

完成条件：能发现分处不同片段的尺度冲突；能区分同词异义；分支确实按已同意的前提执行，而不只是更换标题。

### P1：报告应形成可修订论证，而不是步骤摘要拼接

位置：[最终报告组装](../../hermeneut/research/workspace.py:132)。

当前最终文稿连接全部步骤的摘要，容易混入重复内容、早期解释和后续修订，读者需要自行判断哪个结论仍有效。

建议将每项论点与支持证据、反例、修订状态和未决问题关联；报告正文采用当前有效论点，历史解释保留在过程记录中。输出研究问题、论点、材料依据、反例回应、覆盖限制和未决问题；段落保留可点击引用，不强制综合互相竞争的解释。

完成条件：被撤回／取代的解释不会以同等有效结论进入正文，用户能直接编辑文稿并逐项核验。

### P1：桌面首次启动和后台服务闭环

位置：[桌面 sidecar 启动](../../src-tauri/src/sidecar.rs:14)、[后端入口选择](../../hermeneut/desktop_entry.py:10)、[前端连接默认值](../../web/src/features/research/client.ts:21)、[服务监督进程](../../hermeneut/research/supervisor.py:7)。

默认 sidecar 仍使用 8000 端口，未配置研究数据库时选择旧 API；统一前端默认访问 8010。研究模式的单独 sidecar 也只启动 API，没有同时启动 Worker。现有安装包验证尚不足以证明干净机器上可以直接使用统一研究功能。监督进程发现子进程退出后会整体退出，尚没有经验证的自动重启策略。

建议首次启动检测统一服务是否就绪，用简短向导选择已有服务或本机部署；检查 API、Worker 和数据库修订的一致性。明确服务由谁负责启动和恢复，避免程序看起来已打开、任务却一直排队。重建当前版本安装包并在干净机器验证。

完成条件：无开发环境的机器只需一个服务地址即可导入和研究；API 或 Worker 退出时有可理解的状态及恢复路径。

### P2：让质量案例工具不能“空结果通过”

位置：[机械检查](../../scripts/quality-cases.py:179)、[脚本退出结果](../../scripts/quality-cases.py:251)。

现有工具写出评议表后返回 0，没有将研究失败或缺少产物作为运行失败；某些 `all(...)` 检查在产物为空时仍为真。它没有自动判定学术质量，这一边界正确，但机械检查仍应首先确认确有成功完成的任务及足够产物。

建议把技术执行结果、证据完整性和人工学术评议分开：研究失败时退出非零并列明失败步骤；任务等待决定时标为未完成；产物为空时不能判来源完整。增加真实响应的脱敏回归样例，在不重复调用付费模型的情况下复现本轮定位错误。

完成条件：两次本轮失败在工具中明确显示技术未通过；学术结论继续留给研究者判断。

## 4. 建议实施顺序

1. 引文精确定位、有限修正及独立调用记账。
2. 重跑 Q-03、Q-05，再逐步扩展至全部八例；不通过时不进入学术质量签认。
3. 选区范围闭环、跨文本证据传递、分支前提传递。
4. 当前有效论点驱动报告与写作。
5. 统一桌面首次启动、服务恢复及当前安装包验证。

真实扫描件 OCR、目标对象存储策略、系统重启和正式切换签认继续按既有验收清单推进。优先修复实际阻断，再扩展功能数量。
