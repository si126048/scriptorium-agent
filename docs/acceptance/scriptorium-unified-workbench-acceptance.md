## 2. 状态和结论规则

| 状态 | 含义 |
|---|---|
| 已有验证证据 | 前序实测或自动化测试曾通过；仍需确认与最终版本一致 |
| 部分验证 | 已实现且部分路径通过，仍有必测分支、环境或人工审查未完成 |
| 待验证 | 没有足够执行证据，不能按“代码存在”判为通过 |
| 已发现问题 | 已观察到错误，修复后需要重新验证 |
| 不在范围 | 团队邀请、复杂角色、实时多人编辑及额外模型供应商平台 |

验收结果分为四项，分别签认：

1. **工程验证**：数据完整、权限、任务恢复、构建、安装和部署是否成立。
2. **产品使用**：研究主流程是否在同一工作台内自然完成，操作与状态是否清楚。
3. **学术方法质量**：构境、内在批判、视差和论证是否具有具体、可反驳的材料依据。
4. **数据切换**：迁移异常是否审查完毕，备份和回退是否可执行。

工程测试通过不能代替学术质量验收；演示流程通过不能代替真实模型验收；迁移预演不能代替正式切换。

## 11. 本轮改动

以下改动只针对可在此环境验证的缺口，不改变第 2 节的结论规则。第二轮（P0—P6）的改动见 11.1。

1. **任务版本安全（GAP-02）**：`SUPPORTED_JOB_KINDS` 与 `claim_job(kinds=...)` 限制 Worker 只领取自己实现的类型；无法识别的任务由 `release()` 放回队列，恢复尝试次数并只记录一条 `UNSUPPORTED_JOB_KIND` 事件。`/health` 暴露 `version` 与 `job_kinds`，新增 `GET /api/v2/system/status` 与 `cli doctor` 供升级前后核对。
2. **引用全量重核（GAP-05）**：新增 `cli verify-anchors --report`，逐条核对锚点与不可变文本，列出 `SEGMENT_MISSING`／`QUOTE_MISMATCH`／`MATERIAL_REVOKED`。正式切换检查表中的“已核验引用全部可定位”现在有可执行命令。
3. **OCR 状态（MAT-05）**：成功写入 `metadata.ocr.state=succeeded`、版本号、语言与空页列表；失败写入 `state=failed` 与错误码，且不生成新版本、原件保持可下载。混合文档（部分页有文本、部分页需 OCR）保留可读页，并把未能识别的页列入 `empty_pages`／`ocr_unavailable_pages`，全部页面都无文本时才整体失败。
4. **文稿状态（UI-04）**：文档区显示未保存修改与已保存版本的差别；本地草稿与已保存修订分开保存；工作区保存遇到 409 时取最新 revision 重试一次而不是静默丢弃。
5. **版本对照（MAT-04）**：原文区新增“比较上一版”，按 `xml:id` 逐段列出修改、新增、删除；单版本时按钮禁用，不制造虚假对照。
6. **最新版本判定**：同一秒内写入两个文本版本时，`最新文本` 过去可能取到旧版；现在按修订链的末端（无后继者的版本）判定，`revise_text` 的父版本也使用同一规则。
7. **新增测试**：旧 Worker 版本错配、系统状态与队列视图、CLI 报告与引用重核、S3 适配器（两项）、OCR 失败状态、空页报告，共 7 项，全量由 321 增至 328。

5. **质量案例（P5）**：`scripts/quality-cases.py` 内置 Q-01…Q-08 材料与问题，跑通统一研究流水线，输出每案例产物与待填评议表；`--mode live` 缺 key 时直接报错，禁止用演示结果充当学术证据。
6. **旧业务矩阵（P6）**：`tests/test_legacy_matrix.py` 覆盖 OLD-01…OLD-06 的 API 级行为。
7. **验收运行器**：新增 `capabilities` 步骤（rapidocr／tesseract／S3 端点是否就绪）、把脚本与全部研究测试纳入 Ruff 与专项套件、源库散列比对。

未完成、且不应由上述改动推断为完成的部分：真实模型学术质量（第 7 节案例）、机构对象存储的版本与保留策略、真实中文扫描样张、干净机器上的桌面 GUI 启动与系统重启、Compose、正式迁移的停写与签认。
