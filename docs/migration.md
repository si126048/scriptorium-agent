# 从旧工作台迁移

3.6.0 当前代码仅保留 ACP/MCP 插件。Web、Tauri、常驻后台、PostgreSQL/ES 研究服务、旧 CLI 和安装器已退出当前 Git 树；不再提供 `scriptorium-legacy*` 命令。

旧工作台恢复点：`62336a8e83cdf90a138829e939284cfe7fda18dd`。需要查阅旧实现时可在独立目录检出该提交，避免覆盖当前资料。当前版本不会停止用户已有进程、卸载旧应用或改写旧数据库。

## 资料由使用者主动选择

1. 保留旧程序、源库与备份，在原有可用环境导出所需材料和文稿。
2. 创建新的研究目录，接入当前插件。
3. 自行选择导出的 TXT/Markdown 或提取后的文本，通过 `source_import` 导入。
4. 明确书目、节选和正文身份。旧证据不能仅凭标题自动迁为核验通过；须对导入文本重新定位。

插件不自动导入本次对话中的题目或推荐文献，不扫描旧项目。未在当前包实现的访谈、Persona、TopoStyle 和旧研究调度不被宣称已迁移；可继续在旧版中只读查阅或显式导出。

## 数据库边界

默认库位于工作区 `.scriptorium/research.sqlite3`。3.6 早期上下文插件创建的工作区库可继续使用，已有材料 ID、散列和精确位置保留；文稿表以新增方式建立。普通旧桌面/业务库会在只读检查阶段被拒绝，不能通过 `--database` 冒充插件库升级。

本轮只清理程序与分发文件。用户已有材料、数据库、输出、密钥存储、备份和历史安装包未删除。此前本机研究测试样本保存在被忽略的本地输出目录，不随 Git、wheel 或 ZIP 分发。
