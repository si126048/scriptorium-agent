# 个人研究工作台 3.3.0 操作说明

本轮改进围绕阅读、会话和写作，不要求设置服务器。原桌面一键启动及外部连接入口保留，启动基础说明仍见 [桌面一键启动记录](acceptance/desktop-oneclick-20261025.md)及[现有运行说明](integrated-workbench-runbook.md)。

## 从材料到文稿

1. 选择项目，打开“项目材料”；批量选取文件。重复散列默认跳过，确有多个登记需要时明确选择“仍单独登记”。登记完成不等于文本处理完成，状态见材料列表。
2. 在库内搜索并按用途和状态筛选；点击打开原文。分页以文本版本固定，书页号与阅读页码含义不同。引文打开其原来版本，不会跳到最新修订。
3. 选中原文直接保存笔记，系统同时登记证据。研究输入框展示当前范围；切换会话会恢复目标会话自己的范围与文档。
4. 在文档列表中筛选笔记、报告或文稿；菜单可固定、归档、填写关联研究问题。归档使用筛选恢复访问。
5. 文稿章节目录可切换、排序及新建。打开笔记后“插入当前写作位置”会写入最近选定的主稿或章节，引用节点随内容保留。没有写作位置时可加入新文稿。
6. 书目展开面板支持本地字段与 CSL JSON，选择条目后保存；缺失提示不会虚构作者或出版日期。引用标签来自已登记书目。

## 保存、冲突与导出

自动保存、立即保存、章节切换、接受修改和导出共用保存队列。保存失败时依赖操作停止，本机草稿保留；连接恢复后重试立即保存。

如果另一窗口已经修改同一修订，先比较远端与本机草稿。可采用远端（原草稿另行保留），也可将本机内容另存为独立文稿副本。不要以刷新代替解决冲突。

修改建议面向当前主稿或章节。建议生成后又编辑了正文，旧建议可能因版本过期被拒绝，这是防止覆盖新编辑的修订检查；重新生成建议即可。

导出会先保存，并在提交时固定主稿、章节和引用书目快照。后台生成期间可以继续编辑，已经提交的文件不随之改变。“本文稿的后台任务与下载”保留任务结果，离开再返回仍可重新下载。撤回材料或失去项目权限后，相应下载会受限。

## 窗口与恢复

窄屏一次显示对话或文档，通过关闭文档回到对话，通过项目导航抽屉切换会话。阅读位置和草稿按会话及文档身份保存；不要清理浏览器数据来处理保存冲突。多窗口并发仍使用版本检查，不支持实时多人协同。

服务连接短暂中断时保留当前内容；事件续传恢复后按受影响资源更新。修改建议和导出由后台 Worker 执行，窗口关闭不等于任务取消。

## 候选与回退

候选构建、散列和实际验证见 `acceptance/stable-personal-workbench-20261025.md`。本轮未安装到当前用户正式目录，也未正式迁移研究数据。安装或切换前保留数据库及对象备份；回退前保全新版新增内容。不要让旧程序直接覆盖较新数据。


## 开发者生成候选

先完成前端构建，再冻结代码与静态资源。若仓库中普通后端 EXE 正在被现有桌面服务使用，不应为覆盖构建输出而终止研究服务。本轮使用：

```powershell
python -m PyInstaller scriptorium.spec --distpath desktop-build/stability-stage --workpath desktop-build/pyinstaller-tmp --noconfirm
Copy-Item -LiteralPath desktop-build/stability-stage/scriptorium-backend.exe -Destination src-tauri/bin/scriptorium-backend-x86_64-pc-windows-msvc.exe -Force
cargo tauri build --config src-tauri/tauri.conf.json --bundles nsis
```

先确认架构 sidecar 目标也未被占用；不要仅按端口停止未知程序。最终使用打包后端在独立数据库做冒烟，记录与安装包对应的散列。
